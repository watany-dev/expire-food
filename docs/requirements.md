# 賞味期限・消費期限管理ウェブアプリ 要件定義書

## 1. 概要

スマートフォンのブラウザから利用する、食品の賞味期限・消費期限管理ウェブアプリ。
商品を写真で撮影し、AIで商品名と期限を読み取って登録する。登録した商品は期限の近い順に一覧表示する。

### 1.1 基本方針

- ユーザー登録・ログインは行わない
- Cloudflare + Hono で構築し、無料枠〜低コストで運用する
- 写真は期限の読み取りにのみ使用し、保存しない
- 通知機能は持たない

## 2. システム構成

| 要素             | 技術                                  | 用途                               |
| ---------------- | ------------------------------------- | ---------------------------------- |
| アプリケーション | Cloudflare Workers + Hono             | API・画面配信（Hono JSX）          |
| データベース     | Cloudflare D1                         | スペース・商品データの保存         |
| 画像解析         | Cloudflare Workers AI（Visionモデル） | 写真から商品名・期限・種別を抽出   |
| クライアント     | PWA                                   | ホーム画面への追加、アプリ風の起動 |

- R2は使用しない（画像を保存しないため）
- Cron Trigger は使用しない（通知なしのため）

## 3. ユーザー識別と共有

### 3.1 スペース

- 初回アクセス時に推測不能な `space_id`（UUID v4 等）を発行する
- `space_id` は以下の2箇所で保持する
  - Cookie（HttpOnly, Secure, SameSite=Lax, 有効期限1年）
  - URL（`/s/{space_id}`）
- 1スペース = 1世帯（共有単位）とする

### 3.2 共有・機種変更

- 設定画面に共有URLを表示し、コピーできるようにする（Web Share API が使える端末では共有シートでも送れる）
- 共有URLを開いた端末は同じスペースを利用できる（家族共有・機種変更に対応）
- URLが鍵となるため、「共有URLを作り直す」機能を用意する
  - 再生成後、旧URLではアクセスできなくなる
  - 再生成した端末のCookieは新しいIDに更新する

## 4. 機能要件

### 4.1 商品登録

1. 追加フォームの先頭の大きな「📷 撮影して読み取る」ボタンからカメラを起動する（`<input type="file" accept="image/*" capture="environment">` を見た目だけ隠し、ラベルで起動する）
2. 撮影した画像をクライアント側で長辺800px程度にリサイズ・JPEG圧縮する
3. `POST /api/extract` に送信し、Workers AI で以下を抽出する
   - 商品名
   - 期限日
   - 種別（賞味期限 / 消費期限）
   - 段階的に処理する（[ADR 0007](./adr/0007-staged-extraction.md)）: 読み取りモデル（Gemma 4）が印字の原文を返し、日付の成立・必須項目・登録済みの商品名との一致をコードで確かめ、候補が複数残って決めきれないときだけ判定モデル（Jev）に選ばせる
   - 読み取り中は撮った写真の縮小画像とスピナーを出す（縮小画像もメモリ上だけで扱い、読み終えたら消す。動きを減らす設定ではスピナーを回さない）
4. 抽出結果を登録フォームに反映し、ユーザーが確認・修正する
   - 決めきれなかった商品名・期限は候補を示して選ばせる
   - 期限が読めなければ、写真の期限の部分を指で囲んで、その部分だけを再読する。ピンぼけ・印字欠け・反射で読めないとき、または再読でも読めないときは撮り直しを促す
5. 保存ボタンで登録する。続けて登録するときは「保存して次を追加」で、直前のタグと種別を引き継いだ追加フォームへ進む

**フォールバック**

- 抽出に失敗した場合、または項目が読み取れなかった場合は空欄のまま手入力できる
- 写真を撮らずに手入力のみで登録することも可能とする
- 商品名は、同じスペースに登録済みの商品名（重複なし）を入力候補に出す。読み取りで決めきれなかった候補はその前に足す
- 期限日は「今日 / +3日 / +1週 / +1か月」のチップでも入れられる（JST の今日が基準。JS があるときだけ表示）

**入力項目**

| 項目   | 必須 | 備考                |
| ------ | ---- | ------------------- |
| 商品名 | ○    |                     |
| 期限日 | ○    | 日付（YYYY-MM-DD）  |
| 種別   | ○    | 賞味期限 / 消費期限 |
| メモ   | ×    | 任意のテキスト      |
| タグ   | ×    | 4.6 のタグから 1 つ |

### 4.2 一覧表示

- スペース内の全商品を期限日の昇順で表示する（期限切れが先頭に来る）
- 各行に商品名・タグ・期限日・種別・残り日数を 1 行で表示する（タグで絞り込み中はタグを省く）
- 「期限切れ / 期限の近いもの（14 日以内。`warn_days` がそれより長ければ `warn_days` まで）/ それ以降」に区切って件数を出す。「それ以降」は先頭 2 件だけ出し、残りは畳む
- 表示ルール

| 状態         | 条件                            | 表示                   |
| ------------ | ------------------------------- | ---------------------- |
| 消費期限切れ | 種別が消費期限で、期限日 < 今日 | 赤字＋「消費期限切れ」 |
| 賞味期限切れ | 種別が賞味期限で、期限日 < 今日 | 灰色＋「賞味期限切れ」 |
| 期限間近     | 残り日数 < `warn_days`          | 黄色                   |
| 通常         | 上記以外                        | 通常表示               |

- 賞味期限切れは「おいしく食べられる目安」を過ぎただけで食べられることが多いので、消費期限切れより弱く表示する。どちらも「期限切れ」の区切りに入れる
- 登録が無いとき（タグで絞り込み中を除く）は、「撮る → 確認 → 保存」の流れ、大きな追加ボタン、共有URLで家族と一緒に使えることを案内する
- 期限切れの商品は自動で非表示・削除しない（ユーザーが削除するまで残る）
- 日付の判定は日本時間（JST）で行う

### 4.3 削除

- 各商品に削除ボタンを配置する。行を左にスワイプすると表示する。編集画面の下からも削除できる
- 押下時に確認ダイアログを表示し、承認した場合のみ削除する
- 削除後は一覧の上に「◯◯を削除しました」と表示する
- 「消費済み」ステータスは持たず、削除に一本化する

### 4.4 編集

- 一覧から商品を選択し、登録内容（商品名・期限日・種別・メモ）を修正できる
- 追加・編集して保存したら、一覧のその行へ移動して一瞬強調する

### 4.5 設定

- 期限間近（黄色）とする日数 `warn_days` を変更できる（デフォルト: 3、範囲: 1〜30）
- 設定はスペース単位で保存し、共有している全端末に反映される
- 共有URLの表示・コピー・送信（共有シート）・再生成

### 4.6 タグ

- 食事・菓子・酒のように、スペースごとにタグを作れる（名前は 1〜20 文字）。1 商品に付けられるタグは 1 つまで（任意）
- 一覧の左上のメニューからタグで絞り込める。メニューからタグの追加・削除画面へ移れる
- タグを削除しても商品は消えず、タグなしに戻る
- 決定は [ADR 0011](./adr/0011-tags.md)

## 5. 画面構成

| 画面       | 主な内容                                                                                                       |
| ---------- | -------------------------------------------------------------------------------------------------------------- |
| 一覧       | 期限ごとに区切った商品リスト（色分け）、追加ボタン（右下に固定）、各商品の削除ボタン（スワイプ）、設定への導線 |
| 追加・編集 | カメラ起動、読み取り中表示、確認フォーム、保存ボタン                                                           |
| 設定       | 黄色表示の日数、共有URL（コピー・再生成）                                                                      |
| タグ       | タグの一覧・追加・削除（一覧の左上のメニューから開く）                                                         |

## 6. データモデル（D1）

### 6.1 spaces

| カラム     | 型      | 備考             |
| ---------- | ------- | ---------------- |
| id         | TEXT PK | space_id（UUID） |
| warn_days  | INTEGER | デフォルト 3     |
| created_at | TEXT    | ISO 8601         |

### 6.2 items

| カラム     | 型      | 備考                                |
| ---------- | ------- | ----------------------------------- |
| id         | TEXT PK | UUID                                |
| space_id   | TEXT    | spaces.id                           |
| name       | TEXT    | 商品名                              |
| expires_on | TEXT    | YYYY-MM-DD                          |
| kind       | TEXT    | `best_by`（賞味）/ `use_by`（消費） |
| memo       | TEXT    | NULL可                              |
| tag_id     | TEXT    | tags.id。NULL可（タグなし）         |
| created_at | TEXT    | ISO 8601                            |

- インデックス: `(space_id, expires_on)`

### 6.3 DDL例

```sql
CREATE TABLE spaces (
  id TEXT PRIMARY KEY,
  warn_days INTEGER NOT NULL DEFAULT 3,
  created_at TEXT NOT NULL
);

CREATE TABLE items (
  id TEXT PRIMARY KEY,
  space_id TEXT NOT NULL REFERENCES spaces(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  expires_on TEXT NOT NULL,
  kind TEXT NOT NULL CHECK (kind IN ('best_by', 'use_by')),
  memo TEXT,
  created_at TEXT NOT NULL
);

CREATE INDEX idx_items_space_expires ON items(space_id, expires_on);
```

タグは `migrations/0002_tags.sql` で追加した。

### 6.4 tags

| カラム     | 型      | 備考                         |
| ---------- | ------- | ---------------------------- |
| id         | TEXT PK | UUID                         |
| space_id   | TEXT    | spaces.id                    |
| name       | TEXT    | タグ名（スペース内で一意）   |
| created_at | TEXT    | ISO 8601（メニューの並び順） |

## 7. API

すべてのAPIは Cookie または URL の `space_id` でスペースを特定する。他スペースのデータにはアクセスできない。閲覧（GET）ではスペースを発行しない。

| メソッド | パス                | 内容                                                     |
| -------- | ------------------- | -------------------------------------------------------- |
| POST     | `/api/extract`      | 画像を受け取り、商品名・期限日・種別を返す（保存しない） |
| GET      | `/api/items`        | 商品一覧（expires_on 昇順）                              |
| POST     | `/api/items`        | 商品登録                                                 |
| PATCH    | `/api/items/:id`    | 商品更新                                                 |
| DELETE   | `/api/items/:id`    | 商品削除                                                 |
| GET      | `/api/space`        | スペース設定取得（warn_days）                            |
| PATCH    | `/api/space`        | スペース設定更新（warn_days）                            |
| POST     | `/api/space/rotate` | 共有URL（space_id）の再生成                              |
| GET      | `/api/tags`         | タグ一覧（作成順）                                       |
| POST     | `/api/tags`         | タグ作成（同じ名前があればそれを返す）                   |
| DELETE   | `/api/tags/:id`     | タグ削除（付いていた商品はタグなしに戻る）               |

### 7.1 `/api/extract` レスポンス例

```json
{
  "name": "牛乳",
  "expires_on": "2026-10-05",
  "kind": "use_by",
  "confidence": "high",
  "next": "confirm",
  "name_candidates": [],
  "date_candidates": []
}
```

読み取れない項目は `null` とする。

- リクエストは multipart の `image` と、任意の `part`（`all`（既定）/ `date`。`date` は期限の部分だけを切り出した画像の再読）
- `confidence`: コードだけで期限が決まれば `high`、判定モデルが選んだ期限は `medium`、決まらなければ `low`
- `next`: `confirm`（確認して保存）/ `reread`（期限の部分を切り出して `part=date` で再読）/ `retake`（撮り直し）
- `name_candidates` / `date_candidates`: 決めきれなかったときの候補（決まった項目は空）

## 8. 非機能要件

### 8.1 画像・AI

- 画像サイズ上限: 2MB（クライアントでリサイズ後に送信）
- 画像はリクエスト処理中のみメモリ上で扱い、保存・ログ出力しない
- Workers AI の応答は必ずバリデーションする
  - JSONとしてパースできること
  - 読み取りモデルには正規化させず、印字の原文を返させる。期限の判定はコードで行い、判定モデルの答えも候補に含まれ確信度が十分なものだけを採る
  - 日付の正規化（`26.10.05`、`2026/10/5`、`R8.10.5`、年省略表記などに対応）
  - 年が省略されている場合は、今日以降で最も近い日付として補完
  - 「賞味期限」「消費期限」の文言から種別を判定、不明時は `best_by` を初期値としてユーザーに確認させる

### 8.2 セキュリティ・制限

- `space_id` は十分な長さのランダム値とし、連番や推測可能な値を使わない
- `/api/extract` は space_id ごとにレート制限を設ける（例: 1分あたり10回）。スペースを量産して回避できないよう、接続元ごとにも制限する
- 入力値のバリデーション（文字数上限、日付形式、kind の値）
- スペースの発行は接続元ごとに制限する（1分あたり5回）。1つのスペースの商品は500件、タグは100個まで

### 8.3 コスト

- Cloudflare Workers / D1 / Workers AI の無料枠内での運用を想定
- 画像保存を行わないためストレージ費用は発生しない

### 8.4 対応環境

- iOS Safari、Android Chrome の最新版
- スマートフォン縦画面を主対象とする

## 9. 対象外（スコープ外）

- ユーザー登録・ログイン
- 期限の通知（プッシュ通知・メール等）
- 画像の保存・表示
- 消費済み履歴の管理
- バーコード読み取り
