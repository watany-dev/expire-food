# ADR 0013: 判定モデル（Jev）を高補正モードでだけ使う

- 状態: 採用
- 日付: 2026-09-26
- ADR 0007 の「判定」段を、常に使うものからユーザーが選ぶものに変える

## 背景

ADR 0007 では、コードで決めきれず候補が複数残ったときに毎回 Jev（`typesafe/jev`）を呼んでいた。しかし次の理由で、効果があるかどうか分からない。

- 期限の候補が複数あれば、Jev の答えに関係なく `next` は `confirm` になる（`decide`）。Jev があっても再読は減らない
- Jev が選んだ期限は `confidence: medium` なので、フォームは結局確認を促す。Jev なしとの違いは、候補から選ぶ 1 タップが減るかどうかだけ
- 入出力の形は公開資料から推測したもので、まだ実物で確かめていない。応答を読めなかったり呼び出しに失敗したりしても候補がそのまま出るので、利用者からは区別がつかない
- 呼べば、そのぶん応答時間と Neurons が増える

## 決定

- `/api/extract` に `judge`（`on` / `off`、既定は `off`）を足し、`on` のときだけ判定段を通す（`extractItem` の `judge` を省略すると判定しない）
- 追加・編集フォームの写真の欄に「高補正モード」のチェックボックスを置く。既定は off。比べやすいよう、選択は端末の `localStorage` に覚えておく（読めなくても既定の off で動く）
- `bun run extract-eval` は写真ごとに読み取りモデルを 1 回だけ呼び、判定なしと高補正モードの 2 通りの結果を並べて出す

## 影響

- 既定では 1 回の読み取りで AI を 1 回（部分再読を入れて 2 回）しか呼ばない
- 高補正モードの結果が判定なしより良いと分かれば既定を on に戻し、変わらなければ Jev と `src/domain/judge.ts` を消す。どちらにするかは ROADMAP Phase 3 の実物写真での確認で決める
