# ADR 0011: 商品をタグで分け、一覧の左上から絞り込む

- 状態: 採用
- 日付: 2026-09-26

## 背景

食事・菓子・酒のように種類の違う商品が 1 つの一覧に混ざると、「今晩のおかずで期限が近いもの」のような見方ができない。分け方は世帯ごとに違うので、決まった分類ではなくスペースごとに作れるタグにする。

## 決定

- `tags` テーブル（`id` / `space_id` / `name` / `created_at`、`(space_id, name)` で一意）を足し、`items.tag_id` で 1 商品に 0〜1 個のタグを付ける（`migrations/0002_tags.sql`）
  - 複数タグは付けない。絞り込みの操作と行の表示が 1 つで済み、「分類する」用途には足りる
  - タグを消すと付いていた商品は `ON DELETE SET NULL` でタグなしに戻る
  - 他スペースのタグ ID が送られても、INSERT / UPDATE の中のサブクエリで `space_id` を確かめて NULL にする（エラーにはしない）
  - 共有 URL の作り直し（ADR 0004）では items と同じく `space_id` を付け替える
- 一覧のヘッダー左上に「☰」ボタンを置き、`popover` のメニューに「すべて」・各タグ・「タグを編集」を並べる。JS は使わない（ADR 0002）
  - 絞り込みは `/?tag=<id>`。見出しをタグ名にし、行のタグ表示は省く。知らない ID なら全件を出す
  - 絞り込み中の「＋ 追加」はそのタグを選んだフォーム（`/items/new?tag=<id>`）を開く
- タグは `/tags` で追加・削除する（名前は 1〜20 文字。同じ名前の追加は既存のものを返す）。名前の変更は今は持たない
- 追加・編集フォームは、タグが 1 つ以上あるときだけ「タグ」の選択欄を出す
- API: `GET/POST /api/tags`、`DELETE /api/tags/:id`。商品の `tag_id` は `POST /api/items`・`PATCH /api/items/:id` で付け外しする

## 影響

- 一覧・編集画面で読むクエリが 1 つ増える（一覧は `batch()` にまとめて往復は 1 回のまま）
- 名前を変えたいときは作り直して付け直す必要がある。要望があれば `PATCH /api/tags/:id` を足す
